---
title: "A Read-Only Audit, and What Green Suites Hide"
date: 2026-09-01
---

A full read-only audit ahead of the tournament: nineteen findings, plus four more defects that only turned up by measuring. **Every one was in code the test harnesses structurally cannot reach** — which is the single most useful thing about this pass. A green suite was never evidence about any of it.

## The four criticals

**1. The mid-day early close was never broadcast.** The market-close sync was sent from exactly one place — the bell — and the "one trader left" branch that ends a hardcore round mid-day had no copy. The host closed, clients sat in an open market forever, and the next day bounced off a guard that requires an idle state. **Lobby unrecoverable.** Live on Trader Royale, which forces that mode and whose decider day ends in precisely that branch. The broadcast now lives *inside* the close function behind a server check, so the bug class is unrepresentable rather than fixed.

**2. Item purchase over the network gave any peer any item, free.** No price check, no funds check, no slot check, no draw check. And it had **no production caller at all** — the real path is a different RPC — so the only thing invoking it was the multiplayer test driver. **The MP suite was pinning the exploit in place.**

**3. The rejoin pause had no watchdog.** It stops the simulation for everyone while a reconnecting client verifies its chart, and it only exited on a good hash, five bad ones, or that peer disconnecting. A connected-but-silent client froze all 24 players indefinitely. There's now a 30-second timeout that resumes, hands the seat to a bot, then kicks — and it has to live on the network process loop, because disabling processing is exactly what kills the timer a naive fix would use.

**4. Position relay was quadratic** — one broadcast per inbound packet, about **10,580 host sends per second** at the player cap. Now one batched array at the same rate, around 460 sends, with remote players interpolating instead of snapping.

## Four more, and a lesson in each

**Stake multiplier never reached clients, and two code comments claimed it did.** A client who bought the High Roller upgrade kept a 1.0 mirror, so every casino booth drew them the *un-buffed* stake ladder — real money for an upgrade that visibly did nothing on their machine. The lesson: **it was in the account's `serialize()` method, and nothing in the game calls that.** Being in a serializer is not evidence a field syncs. The RPC's argument list is.

**Margin used was derived on the receiver** as shares × entry price. Right for an ordinary open, wrong for an *assumed* position — a fire sale or a block trade, where the figure is the bid. Position value is margin plus unrealised, so a client who bought a margin-called book overstated their own equity on the HUD, the leaderboard and the tablet for the position's entire life. Both fields now travel, defaulting to −1 rather than 0 so an older build degrades to the old derivation instead of to "worth nothing".

**Fifty booth drum viewports were running at full update, 512², with no visibility or distance check** — roughly 3,000 render passes a second of pure set dressing, in the same room as the 100 desk faces that are carefully throttled. Now a 7 Hz sweep with culling at 256², about 97% off. Seven hertz rather than the desks' half-hertz because these faces carry sub-second pulses that a slower sample aliases into flicker.

**The closing auction filled off the bar's open**, a no-op at the bell but not on the mid-day close above. Worth noting that the obvious fix is the wrong one and looks right: the "live price" accessor only moves on price updates, which are suppressed once the tick is inactive — i.e. exactly during a bell close.

## The strongest new test is an arity check

Three of the bugs above are the same shape: a field on one side of a sync that never made it to the other. Naming the three missing fields in a test would only catch the bugs already found.

So the new assertion **counts the arguments the sender sends against the parameters the receiver declares**. That catches the *next* field added to one side and not the other — which is the actual recurring defect, and which no assertion on account values can ever see, because a defaulted parameter makes the omission look like a perfectly legal call.

## The regression the review caught

**Replacing 23 per-peer relays with one broadcast is only a win if the one packet still fits.**

The batched array measured **1,984 bytes at the 24-player cap — 142% of a 1400-byte MTU** — and the RPC is unreliable, so the network layer splits it and losing either fragment drops the whole update. It fragmented at exactly the size the tournament runs at, and nowhere smaller. Now packed integer and float arrays: **496 bytes, 35% of MTU**, pinned by a test that measures the encoded size against the limit. A string array of agent ids was measured and rejected at 87%, because **the payload grows with the player's name** and platform names run to 32 characters.

## Two frame-rate couplings

Neither is networking, both matter at a LAN:

- **The order book healed once per `update()` — i.e. per frame.** A 144 Hz host gave a deeper market than a 60 Hz one, for all 24 players. Now a fixed timer.
- **The drought jitter was drawn from the shared seeded generator every frame**, so **the same seed produced a 13–28% different close depending on frame rate.** Now cached per bar, with a rendered before/after.

## Floor throughput was linear against a geometric curve

The per-tick order budget was `$10k × current day` — **linear** — while the goal curve compounds at ×1.8828/day. The comment above it claimed it rode the goal curve. It did not, and the gap compounds daily.

Measured against the day's goal, the budget was 16.7× on day 1, 6.6× on day 5, 0.56× on day 10 and **0.002× on day 20**. In ticks, a maximum-size exit took one tick through day 9, six by day 12, 167 by day 18 and **500 against a 480-bar session by day 20 — it could never be exited at all.**

It now derives from the expected bankroll, the same anchor the trade ladder uses. **Day 1 is unchanged to the cent.** The invariant this buys: budget divided by the largest position a player can hold is **flat at ~11× on every day** (measured 10.65–12.00 across days 1–40), where it used to fall from 11× to nothing. The whole floor shouting maximum size clears in three ticks on day 1 and three ticks on day 500.

The trade-off is stated rather than hidden: at days 10–19 an exit that was paced over 6–167 ticks — letting the book heal between them — now completes in one, so it eats more depth in a single go. Strictly better than positions that could not be worked out at all and were force-closed into a thinned book at the bell, but it is a real change to late-game slippage.

The test was rewritten to **sweep days 1–40 asserting the ratio**, not any single dollar figure. This was a wrong *curve*, not a wrong constant, and a spot-check on day 5 would pass on any curve through that point.

## The flaky test that wasn't about what it said

One multiplayer assertion failed about one run in three, and the first guess — a deposit race — was wrong. What was actually happening:

**The client agent was busting itself on the harness's own test trade.** It had bought two stacking margin items, so it traded at 13× against the host's 3× — which is exactly why only the client side ever blew up. A ~9.5% adverse move wiped it, and the bust zeroes the bank balance the *later* ATM test then reads as zero. **Three assertions went red and none of them named the cause.** A failure message about ATM interest sends you to the sync layer, which is where the previous investigation went.

Digging into it turned up three more harness defects, each worse than the flake:

- **The market was random, per process.** Hosting never set the session seed, so each side seeded itself independently. Every market-dependent assertion in the driver was a coin flip on two unrelated markets, and the suite's greenness was partly luck. Pinned now — though note this removes the market as a variable, not the timing.
- **One assertion was `>= 0.0`** — tautologically true. It passed even in runs where the host had never deposited at all, which is how a broken deposit stayed invisible at its own step and resurfaced later under another test's name. Worth hunting for that shape elsewhere.
- **Every NPC executor had a null order book.** The harness scene adds its stubs before the game manager (it must, for group membership), so each registered itself with nothing to trade into. **NPC closes and the entire closing auction threw and did nothing** — four stack traces per run — **while the suite reported 38/38.** Production is fine, and it self-corrects from day 2, which is why it hid for so long.

**A stack trace in a passing run is still a failure.** Both suites print them, both exit zero, and nothing greps for them.

Before: six runs, the one with a bust failed. After: eight consecutive clean runs. Unit suite 1108/1108, MP host 38/38 and client 18/18.

**Also ruled this week:** the overnight section is deferred but explicitly tracked — it's a second area, not a system anything depends on — and the SFX and animation pipeline is gated on the fifth booth being finished. That makes the fifth booth the gate on the largest unstarted workstream, not just on the LAN.
